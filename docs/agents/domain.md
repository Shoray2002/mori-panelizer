# Domain docs

This repo uses a single-context layout.

Before exploring the codebase:
- Read root `CONTEXT.md` when present.
- Read relevant decisions under `docs/adr/`.

If these documents are absent, proceed silently.
Create them through `$mattpocock:domain-modeling` when
terminology or decisions are resolved.

Use the glossary's terms for domain concepts.
If a needed term is missing, reconsider the wording or note
the gap for domain modeling.

If a proposal contradicts an ADR, identify the ADR and explain
why the decision should be reconsidered.
